🤝 Contributing to DealIntel India

First off, thank you for your interest in contributing to DealIntel India.

We appreciate contributions from developers, designers, financial analysts, M&A professionals, product managers, and the open-source community.

Our goal is to build India’s most trusted AI-powered M&A Intelligence Platform for SMEs.

⸻

Code of Conduct

By participating in this project, you agree to:

* Be respectful and professional.
* Be constructive when providing feedback.
* Collaborate in good faith.
* Welcome contributors from all backgrounds.

Harassment, abusive language, discrimination, or inappropriate behavior will not be tolerated.

Before You Start

Please:

* Search existing Issues before opening a new one.
* Discuss major changes before starting development.
* Keep pull requests focused on a single feature or fix.
* Follow the project’s coding standards.

⸻

Development Setup

Clone the repository

git clone https://github.com/divyanshmehta28199902-maker/dealintel-india.git

⸻

Navigate to the project

cd dealintel-india

⸻

Install dependencies

npm install

or

pnpm install

⸻

Start development server

npm run dev

⸻

Branch Naming Convention

Use descriptive branch names.

Examples:

feature/company-analysis
feature/valuation-engine
feature/dashboard-ui
bugfix/login-error
bugfix/valuation-rounding
docs/readme-update
refactor/pipeline-module

⸻

Commit Message Guidelines

Good commit messages help maintain a clean project history.

Examples:

feat: add AI valuation summary
feat: improve investor dashboard
fix: resolve DCF calculation issue
fix: correct company search filter
docs: update README
docs: add roadmap
refactor: simplify valuation engine

⸻

Pull Request Checklist

Before submitting a Pull Request, ensure:

* Code builds successfully.
* No TypeScript errors.
* No linting errors.
* Existing functionality is not broken.
* New features are documented.
* Screenshots are included for UI changes.
* Tests (if applicable) pass successfully.

⸻

Coding Standards

TypeScript

* Use strict typing.
* Avoid the any type whenever possible.
* Prefer reusable components.

⸻

React

* Functional components only.
* Use hooks appropriately.
* Keep components modular.

⸻

Styling

* Tailwind CSS
* Consistent spacing
* Responsive layouts
* Accessible color contrast

⸻

File Naming

Components:

InvestorDashboard.tsx
CompanyAnalysis.tsx
DealMarketplace.tsx

Utilities:

valuation.ts
helpers.ts
formatCurrency.ts

⸻

Reporting Bugs

Please include:

* Expected behavior
* Actual behavior
* Steps to reproduce
* Browser
* Device
* Screenshots (if applicable)

⸻

Feature Requests

Feature requests should include:

* Problem statement
* Proposed solution
* Business value
* Screenshots or mockups (optional)

⸻
